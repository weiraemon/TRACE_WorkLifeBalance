# ATLAS — 基于 Obsidian Vault 的个人工作台

单用户、本地运行。项目是面，业务线是线，关键节点是点，待办挂在节点下。Markdown 是唯一事实来源，无数据库、云服务或应用内 Mock 数据。MIT。

## 运行

Windows + Node.js >=22.12，本地 NTFS 目录，Chrome / Edge。PowerShell：

```powershell
cd E:\Document\GITHUB\TRACE_WorkLifeBalance
npm ci
npm run build
npm start
```

访问 http://127.0.0.1:4317，输入已有 Vault 文件夹的绝对路径。服务只监听本机。开发模式：`npm run dev`；Ctrl+C 停止并释放锁。端口占用时先检查原终端是否已有服务，不重复启动。

先复制 `examples/workspace-vault` 到测试目录，再用 ATLAS 和 Obsidian 打开同一个目录。示例有两个项目、三条业务线、彩色节点、自己 / To / From 待办，以及一条真实落盘的实际记录。也可以向空目录生成日期为当天的示例：

```powershell
npx tsx scripts/sample-vault.ts E:\ATLAS-Trial
```

## 使用动线

| 页面     | 功能                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| 工作空间 | 唯一计划入口。新增和编辑项目 → 业务线 → 关键节点 → 待办，项目可收缩，业务线横向推进 |
| 今日     | 唯一实际录入入口。按重要性排序的单行待办、等 / 找谁，以及计划 / 实际两侧视图        |
| 知识     | 浏览 Vault 和维护资源链接，调用原生编辑器打开资料                                   |
| 回顾     | 本周实际投入、完成待办、阻塞与待反馈、周复盘                                        |

从对应项目 / 业务线 / 节点的按钮新增下一级，归属自动带入，通常只需填标题。节点只维护截止日期和截止时刻；待办不再填日期或时刻。节点不加边框，线上圆点用绿、黄绿、黄、橙、红表示五档重要性，不显示数字比值或徽章。截止时间在圆点上方，标题和无框待办列在下方。点待办前的圆圈即可完成并原位划线，再点一次可恢复手动完成的待办。可选设置折叠。

节点按截止日期、时刻从早到晚排列，未定日期放最后。新增或修改截止时间会自动重排，不需要填写节点顺序。

To 表示需要交给对方，From 表示等待对方交付；今日联络清单用“找 / 等 + 人名”呈现，项目 / 节点归属放在行尾。当天待办以自身重要性排序，省去单独的推荐区，逾期交接仍会提醒。

今日桌面左右均分：左侧今日状况，内部左为工作空间推导的只读计划线，右为实际时间线；右侧上下为当天待办与联络清单。不加卡片外框，用留白和分隔线区分。计划节点按截止时刻定位在线旁，点击向左展开所属待办；未设时刻的节点留在“未定时间”区。今日不提供计划时间输入，不新增计划副本。

今日点击「记录实际」或 Ctrl+K，填开始时间、结束时间、具体事件。可选关联一个或多个待办，区块显示对应名称，同一待办可分多段记录。完成时再勾选“本次完成”，完成状态即时推导；撤回完成勾选可恢复待办，不重复写任务状态。实际时间线支持点击补录、拖动和拉伸，保存修改历史，拒绝重叠计时。

仅支持 `project / workline / milestone / todo / actual / resource / review` 七种记录类型。旧模型、旧计划时间块与兼容入口已删除；没有旧数据迁移。连接 Vault 不会自动删除或改写已有文件。

## 当前边界

- 正文在 Obsidian 编辑，ATLAS 只改结构化字段；保留正文和非 ATLAS 字段。外部修改通过 revision 拒绝覆盖。
- 实际记录的项目归属从关联或完成的待办推导；没有关联的时间列为「未关联」，跨项目列为「跨项目（未分摊）」，不编造耗时分配。
- 业务线和节点通过选择直接上级移动；节点按日期自动排列，其他实体仍可用顺序数字排序；没有空间拖拽、后台计时器、Obsidian Tasks 同步或 AI 自动采集。
- 文件改名按稳定 ID 找回；原生资源按唯一内容指纹寻找。目录重命名、多个相同副本等情况需要手动重关联。
- 备份仅覆盖管理 Markdown，包含正文，不包含附件和普通笔记，不删除快照之后新增的记录；全量 Vault 需独立备份。
- 大 Vault 轮询性能和长时间真实使用尚未验证。多文件恢复不是跨文件事务，最后哈希检查与原子替换间仍存在极窄的外部编辑竞态，详见安全文档。
