# QQ 同步：实施进度与使用

目标：从本人 QQ 的指定群聊或私聊中识别外部要求，确认后进入现有业务线计划。

## 当前交付边界

已实现：会话规则、身份关键词、本地筛选、可切换的 AI 模型接口、持久化待确认事项、确认入计划及 Notes，以及**本机 QQNT 数据库的群聊和私聊自动同步**。绑定群号或私聊 QQ 号后会定时读取，登录后补下来的离线消息也会按原始时间进入识别流程；也可按会话和时间段手动补取。

仍需要的本机依赖：Python 3.12 + `sqlcipher3`，以及一次性的 QQ 数据库密钥提取。没有 Python 时，初始化脚本会尝试 winget，失败后下载官方 Python 3.12 安装程序并安装到当前用户。**图片／附件、自动会话发现、微信数据源尚未接入。**

2026-10-29 接入验证：已在 QQ 9.9.x 的本机 `nt_msg.db` 上完成解密与字段验证；密钥通过登录时的一次性调试获取，数据库参数为 SQLCipher 4、HMAC-SHA512。已验证正文、发送人、群号、时间、@全体和 @我字段；具体消息数量随账号不同，不在文档中记录。没有修改 QQ 安装目录、登录状态或客户端配置，没有安装注入式插件。

## 使用

1. 重启本地服务并刷新页面，连接工作目录，打开顶部“QQ同步设置”。
2. 在“模型设置”配置 AI 模型：可选 DeepSeek、OpenAI / ChatGPT 或自定义 OpenAI 兼容接口，填写接口地址、模型名称和 API 密钥。在“QQ自动同步全局设置”填写本人姓名、班级和 QQ 同步参数。在“会话规则设置”点击“读取 QQ 列表”读取群和联系人，再在“群聊设置”或“私聊设置”中点击对应的添加按钮。群聊规则可输入群名片段或群号搜索，私聊规则可按联系人原名、备注或 QQ 号搜索；选择后自动填入名称，可改短。每条规则可设“限定项目”或“默认业务线”：只设项目时 AI 只在该项目下匹配或新建业务线；设默认业务线则直接使用。模型设置与各提供商密钥保存在本机，保存一次后重启程序无需重输。
3. 每条规则选择全部检查或条件检查。条件为任意命中：@全体、@自己、姓名／别名、班级、指定发送人或关键词。停用会话不发送给模型。每条规则还可开启：
   - “使用 AI 辅助日程添加”：默认开启；关闭后只做规则过滤，消息原样进入待确认，由你手动设置标题、日期、项目和业务线，也可在卡片上再点“用 AI 识别”。
   - “自动加入计划（跳过待确认）”：开启后 task／event 直接创建，不再逐条人工确认；变更／取消建议仍留在待确认，确认后直接修改或取消原事项。默认关闭，建议只给可信的通知群开启。
   - “同步本人发送的消息”：开启后本人消息也会交给 AI；即使规则选择“只检查符合条件的消息”，本人消息也直接检查。默认关闭。
4. 需要补取某个群或私聊的历史消息时，打开“QQ手动同步”：选择已绑定 QQ 的会话规则、开始／结束时间（北京时间），决定是否使用 AI、是否同步本人消息、是否自动加入计划，然后开始。关闭“使用 AI 辅助日程添加”时只把过滤后的原文加入待确认，由你设置项目、业务线和日期；卡片上可用“用 AI 识别”补全。手动同步不会移动自动同步游标，已处理过的消息不会重复；私聊需先在规则里绑定 QQ 号。
5. 待确认页顶部提供“快速处理（本地解析，不调用 AI）”：粘贴一段文字，先提取日期、时刻、标签和可能业务线，再加入待确认；未使用 AI 的卡片里也有同样的本地解析入口和“用 AI 识别”按钮。
6. 在待确认页展开“粘贴 QQ 消息进行识别”，选择会话，填写发送人和原发送时间（北京时间），粘贴正文；@ 标记需对照原消息人工确认，正文里的“@全体成员”不会自动冒充真实 @。
7. 点击识别后，只有命中规则的正文、手工补充的同一会话上下文及必要身份关键词发送到所选 AI 模型。未命中不调用 API。默认使用 DeepSeek `deepseek-flash`，也可切换 OpenAI 或其他兼容接口；JSON 输出再次由本地校验。
8. 核对建议、日期与事项内容后确认。有日期或时刻的要求成为节点；无日期行动进入 AI 决定的业务线待办池；无日期不补今天。变更／取消会在待确认里显示原事项，确认后直接更新或取消原节点／待办，不再要求手工去工作空间改。
9. 归属按“会话默认业务线 → 会话限定项目 → AI 匹配或命名新建”处理，详见下文“归属推荐”。AI 会把新建项目／业务线名称预填到输入框，可直接修改；新归属在确认卡片时才创建，忽略不会改动工作空间。

“微信同步设置”已放置“微信手动同步”和“会话与识别设置”占位，操作结构与 QQ 相同，但尚未接入微信数据源。

### AI 模型与密钥

模型提供商、接口地址、模型名称和该提供商的密钥一起保存在本机用户配置目录，Windows 为 `%APPDATA%\CHAOS\settings.json`，macOS 为 `~/Library/Application Support/CHAOS/settings.json`，Linux 为 `~/.config/chaos/settings.json`。可用环境变量 `CHAOS_CONFIG_DIR` 指定其他目录（建议使用绝对路径）。

- **DeepSeek**：默认 `https://api.deepseek.com` / `deepseek-flash`，环境变量 `DEEPSEEK_API_KEY`。
- **OpenAI / ChatGPT**：默认 `https://api.openai.com/v1`，模型名称需填你账号可用的模型，环境变量 `OPENAI_API_KEY`。
- **自定义**：任意 OpenAI 兼容的 `/chat/completions` 接口（Bearer 认证），环境变量 `CHAOS_AI_API_KEY`。非本机地址必须使用 HTTPS；本机服务可用 HTTP。接口不支持 JSON 输出模式时，可关闭“使用 JSON 输出模式”。

各提供商的密钥分别保存，切换提供商不会把旧密钥发给新接口。清除密钥只影响当前提供商。已保存密钥优先于环境变量；密钥不会随 API 状态返回，不写入 Markdown 工作目录、浏览器存储、备份或日志。文件权限在 macOS／Linux 设为仅当前用户可读写，Windows 继承用户配置目录的访问控制。

未配置可用 API 密钥时，规则和手动同步里的“使用 AI 辅助日程添加”会自动取消并禁用，并提示先配置 API；自动同步会降级为把过滤后的原文加入待确认，不会卡在报错重试。

### 一键初始化（Windows）

首次接入可以双击仓库根目录的 `setup-qq.cmd`。脚本会：

1. 检查 Node.js 22.12+、Python 3.10–3.12；没有可用 Python 时安装 3.12；
2. 缺少 `sqlcipher3` 时自动安装；只使用预编译 wheel，避免触发 Visual C++ 源码编译；
3. 自动定位 QQ 数据目录；
4. 关闭 QQ，下载固定版本的密钥提取脚本并校验 SHA-256；
5. 以调试模式启动 QQ，等待你登录；
6. 捕获所有候选密钥但不打印，逐个用 `nt_msg.db` 验证；
7. 运行 `qq_sync.py test` 验证数据库；
8. 把 QQ 配置写入 `%APPDATA%\CHAOS\settings.json`，保留已有 AI 配置。

默认情况下配置写入后自动同步处于关闭状态，需要打开“QQ同步设置”确认测试并启用。脚本会收集登录过程中出现的多个候选密钥，并逐个用 `nt_msg.db` 实际解密验证；只有验证通过的密钥才会写入配置。已保存且验证有效的密钥会优先复用；如果新密钥与当前账号目录不匹配，还会尝试其他账号目录。密钥提取依赖第三方调试脚本，可能触发安全软件；如不希望自动下载，可先手动下载 `QQBackup/qq-win-db-key` 的 `windows_ntqq_get_key.ps1`，再运行：

```powershell
.\scripts\setup-qq.ps1 -QqKeyExtractorPath "路径\windows_ntqq_get_key.ps1"
```

### QQ 自动同步

先准备本机环境：

1. 安装依赖：`py -3.12 -m pip install sqlcipher3`。同步设置里的 Python 命令默认 `py -3.12`。
2. 一次性提取 QQ 数据库密钥：关闭 QQ，使用 [QQBackup/qq-win-db-key](https://github.com/QQBackup/qq-win-db-key) 的 PowerShell 脚本重新启动并登录一次；脚本会输出 16 位密钥。QQ 升级后可能需要重新提取。
3. 在“QQ同步设置 → QQ自动同步全局设置”填写：
   - QQ 数据目录：包含 `nt_qq` 的账号目录，或直接填 `nt_qq`／`nt_db`，脚本会自动识别；
   - 本人 QQ 号：用于识别和排除自己发出的消息；
   - 同步间隔：默认 30 秒；
   - 首次回填天数：默认 7 天，可设 1–365 天；
   - Python 命令；
   - QQ 数据库密钥。
4. 保存后点“测试读取”，确认能看到群消息/私聊数量；点“读取 QQ 列表”，会同时读取群和联系人，按钮下方提示群与联系人的数量。群聊规则可在“QQ 群”中按群名或群号搜索；私聊规则可在“QQ 联系人”中按原名、备注或 QQ 号搜索，也可直接输入 QQ 号绑定。选择后会自动填充会话名称，可再改短。私聊默认不启用，需要先填写本人 QQ 号后手动勾选。

同步逻辑：

- 只处理已启用、已绑定群号或私聊 QQ 号的规则；未绑定的会话不会读取。
- 群聊按群号读取 `group_msg_table`，私聊按对方 UID 读取 `c2c_msg_table`；私聊要求配置本人 QQ 号以区分收发方向。
- 每轮每个会话最多读取 20 条新消息，同时保存 rowid 与时间游标；QQ 本地插入的低 rowid 新消息也能靠时间窗口补上。
- 首次同步回填最近 7 天（设置中可改为 1–365 天），并额外向前多取 1 天作为缓冲；之后只读游标之后的新消息。
- QQ 重新登录后，服务器下发并写入本地库的离线消息会保留原发送时间；CHAOS 从游标之后读取，因此能补进来。
- 只能补 QQ 本地库已有、或登录后 QQ 实际同步下来的消息；腾讯服务器不再下发的历史无法恢复。群历史有时需要在 QQ 中打开该群才会同步。
- 私聊按每条消息独立处理，连续消息不合并，因此连续发送可能生成多次待确认；不建议用于正常聊天，更适合给自己或大小号快速记事项。
- 默认排除本人发送的消息；规则勾选“同步本人发送的消息”后，本人消息也会交给 AI，且在条件检查模式下直接检查。切换该开关会重置该会话的同步游标，让回填窗口重新检查，避免把开关打开前被跳过的本人消息永久漏掉。
- 只有命中规则筛选条件的消息才调用 AI；默认进入待确认列表。开启“自动加入计划”的规则会直接创建 task／event，变更／取消建议仍留在待确认；确认变更会更新原节点／待办日期，确认完成会标记原事项完成并保留日期，确认取消会把原事项标记完成。
- 同一条消息里标题相同的多个 task／event 建议会合并为一张卡片，行动清单取并集；如果时间不同，保留一个主时间，并在“需要核对”中列出其他时间。同名变更也会合并，优先保留节点目标，避免节点和它下面的待办各弹一次确认。
- 待确认页提供“一键确认”和“一键忽略”，点击后先弹窗确认全部处理；一键确认会逐条执行变更/取消，成功的移出待确认，失败的保留。
- 顶部“QQ同步设置”按钮显示待确认条数，每 10 秒刷新，打开弹窗或处理后立即更新。
- 发给模型的消息同时带 `sentAtLocal`／`sentAtDate`（北京时间），避免“今天”被按 UTC 日期算错；同时携带当前未完成节点与待办。模型返回与现有事项同名的任务时，本地会转为变更待确认，自动加入不会创建重复节点。
- 模型会为有日期或时刻的节点从“会议、报告、讨论、专注、实验、审阅”中选择标签；消息有明确地点时，地点写入节点字段、节点卡片和节点内容首行。
- 同步缓存位于 `%LOCALAPPDATA%\CHAOS\qq-cache`（macOS/Linux 对应用户缓存目录），保存的是剥头后的 SQLCipher 副本，不是明文；可随时删除。
- 非官方方案，QQ 升级可能导致读取失效；密钥和聊天内容只在本机处理，不要上传。

### QQ 手动同步

“QQ手动同步”用于补取某段历史或测试某个群／私聊：

- 选择已绑定 QQ 的会话规则（群聊或私聊）；
- 选择开始、结束时间（北京时间），单次最多 366 天；
- 可勾选“使用 AI 辅助日程添加”；关闭时原文直接进待确认，由你设置项目、业务线和日期，卡片可再点“用 AI 识别”；
- 可勾选“同步本人发送的消息”；
- 可勾选“同步已经同步过的消息”，用于规则改动后重新分析历史；默认跳过已处理指纹；
- 可勾选“自动加入计划（跳过待确认）”，只对 task／event 生效，变更／取消仍待确认；
- 单次最多读取 50 条可识别文本；
- 手动同步会跳过截止日期/时刻已早于当前北京时间的 task／event；变更、取消和时间待定的建议不按此规则跳过；
- 不移动自动同步游标，已处理过的消息通过去重不会重复生成；
- 私聊需要先在规则里选择“个人聊天”并填写 QQ 号。

“微信同步设置”中的“微信手动同步”目前为占位，不读取微信数据。

## 数据与限制

### 归属推荐

每项建议的归属按以下顺序确定：

1. **会话默认业务线**：规则设置了默认业务线时直接使用，不把项目和业务线清单发给模型，模型返回的归属也会被忽略。
2. **会话限定项目**：只设项目、未设默认业务线时，只把该项目及其业务线发给模型。AI 只能匹配该项目内的业务线；匹配不上时在该项目下新建业务线，不会新建项目。
3. **AI 匹配或命名新建**：未限定项目时，把未结束的项目与业务线一起发给模型。模型优先返回现有业务线；项目匹配但业务线不合适时在已有项目下新建；都不匹配时根据消息内容给新项目、新业务线取名，不再返回空归属。
4. **确认时创建**：卡片用输入框预填 AI 生成的项目／业务线名称，可直接修改；确认加入计划时才创建，并复用唯一的同名项目／业务线。

推荐只依据消息正文与会话默认设置，不读取 Notes 正文。模型没有给出归属、编造了归属 ID、越出限定项目、推荐已结束或格式不完整时，系统会按事项标题和消息内容自动生成一个可用归属并提示；限定项目下只会生成该项目的业务线，不会另建项目。归属推荐只针对行动与事件；变更、取消和忽略建议不创建归属。

### 识别结果容错与多事项

模型返回的字段会再次由本地 schema 校验。日期、时刻、标题等不完整时，能保留的保留，不能确认的留空并写入不确定提示；完全无法解析时要求重试。单条通知可拆分多个事项，最多 10 项；同一事件的行动清单不重复拆成事项。

### 数据与安全

- 工作目录 `.atlas/qq-inbox.md` 是规则与待确认事项的权威文件，以 Markdown 中的 JSON 管理块保存；管理块之外的正文原样保留，外部编辑冲突停止覆盖。
- 待确认内容保留到用户确认或忽略，最多 100 条。忽略后删除正文；确认后将必要原文移入业务线 Notes，同时从收集箱移除。不上报整个通讯录、未选会话或项目档案。
- QQ 数据库密钥保存在本机配置目录；同步缓存为用户缓存目录中的加密副本，不进入 Vault 或备份。
- 当前“备份”快照仍只包含已有 ATLAS 管理记录；不包含消息规则与待确认文件。需要保留这些配置时请手动复制 `.atlas/qq-inbox.md`。AI 设置、QQ 密钥永不进入备份。
- 尚不支持自动会话发现、图片／附件识别、原事项语义匹配或改期自动写回。没有真实模型密钥时，测试通过模拟供应商响应验证格式与错误处理，不能代表所有真实模型调用均已通过。
