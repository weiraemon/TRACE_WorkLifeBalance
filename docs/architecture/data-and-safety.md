# 数据契约与文件安全

ATLAS 为单用户本地程序。React → 同源本地 HTTP API → Vault 文件适配器 → Markdown。共享 `packages/domain/index.ts` 负责 Zod 契约、直接父级与完成关联校验、日期与汇总；文件服务不依赖 React。仅一个 npm 包，不创建空的 application/ui/shared 发布包。

## 唯一事实来源

`ATLAS/<type>/<uuid>.md`：每个实体一份 Markdown。Frontmatter 形如：

```yaml
atlas:
  managed: true
  record:
    schemaVersion: 1
    id: 9bfaf27c-6887-4f9e-b8b0-f01bb170ea31
    type: project
    title: 研究策略
    # 其他字段由契约定义
```

记录仅有 project、workline、milestone、todo、actual、resource、review 七种类型。项目 → 业务线 → 节点 → 待办是四个独立实体，分别只保存直接父级 ID；节点只保存截止日期 dueDate 与截止时刻 dueTime，不保存开始日期或时长；待办没有自己的日期 / 时刻。actual 只保存本地日期、起止时间、事件、推进待办 ID（workedTodoIds）、完成待办 ID（completedTodoIds）和修改历史，没有计划模式。完成状态与项目归属从关系即时推导，不重复写一份状态或上级归属。

UUID 不随路径变化。目录只是初始组织方式，扫描按 `atlas.managed` 与 record.id 找回移动的文件。严格契约拒绝未定义类型、额外字段和非 1 的 schemaVersion；没有兼容分支或自动迁移。普通 Obsidian 笔记不被接管；发现不支持的管理记录会显示诊断，不自动删除。旧代码和仓库示例已移除，不扫描或删除用户真实 Vault 的历史内容。

节点正文可在详情页直接编辑，读写同一 Markdown 文件的 Frontmatter 之后的内容，不复制到结构化字段。正文保存仅更新 atlas.record 的更新时间，保留非 ATLAS 字段和注释，并执行 revision 校验与原子写入；普通保存不创建历史快照。属性修改使用 YAML AST 定位 atlas 值的字节范围，替换范围以外的内容逐字保留，包括其他键、注释、CRLF 和正文。打开编辑表单后保留原 revision；轮询不会偷偷改变表单或正文草稿的预期版本。

资源有自己的 UUID，可被多工作引用。Vault 笔记优先按已管理笔记 ID 找回；其他文件移动后按唯一内容指纹匹配。移动同时改内容、多个相同附件或目录重命名无法唯一找回时，明确报错，需手动重关联。外部文件只保存绝对路径并调用默认程序打开，不扫描、不写入。它们从未成为 ATLAS 的第二知识库。

知识页新建 Markdown 仍使用 resource 实体，正文与元数据同存于 `ATLAS/knowledge/<tag 或未分类>/<标题>-<UUID>.md`，noteId 指向自身，不另建资源索引文件。kind 为 note / idea / meeting / draft，tag 为一个可输入的新标签；标签作为单层目录名校验，拒绝路径穿越和 Windows 保留名称。新建使用现有原子发布；同标题使用不同 UUID，互不覆盖。创建后可编辑标题与类型，应用不自动移动笔记目录；在 Obsidian 中移动的笔记按稳定 ID 找回。节点复用 resourceIds，只允许一个 Vault Markdown 引用，解绑不删除原文件。首次绑定普通笔记先保存资源引用、再保存节点；节点保存冲突时资源引用可能独立留在知识页，原文件不变。

节点详情分别保留自身正文和绑定文件页签，显示实际文件名、文件夹及类型颜色。类型优先从最近的 note/notes、idea/ideas、meeting/meetings、draft/drafts（含中文）目录推导，否则使用 resource.kind；只影响显示，不移动或改写目录。正文接口只接受当前节点实际绑定的 resource ID，禁止借此编辑未绑定的其他文件。绑定文件读写隐藏并保留 Frontmatter，保存检查目标全文 revision；普通笔记不再积累历史副本，也不接管为 ATLAS 实体。普通笔记保存后更新资源引用的内容指纹；正文和引用为逐文件原子写入，引用更新失败会明确提示正文已保存。

## 安全读写

1. 只监听 `127.0.0.1`；Host 和 Origin 精确匹配。会话随机 token 必须放在自定义请求头；不启用 CORS，不接受表单跨站写入。
2. Vault 必须为已存在的绝对目录。连接仅创建 `.atlas/service.lock`。一个 Vault 只允许一个 ATLAS 服务写入。
3. 每段路径检查越界、符号链接和 Windows Junction；拒绝 `..`、绝对相对混用、ADS 和可疑尾空格/点。忽略 `.git`、`.obsidian`、`.atlas`、node_modules。
4. 写入排队，内容校验，重复 ID 拒绝保存。普通保存不生成快照；手动快照和必要的删除、恢复前备份保存在 `.atlas/backups/<uuid>.json`。
5. 同目录临时文件 → fsync → 最后内容哈希比较 → 原子替换。新文件用硬链接原子发布，绝不覆盖已存在目标。Windows 需支持硬链接的 NTFS；不支持时失败并报错，不降低安全保证。
6. 临时文件不在索引里展示为正常工作记录。异常退出遗留的 `.atlas-tmp-*` 只诊断，不自动提升覆盖原文。
7. Restore 先检查整批文件和当前 revision，将确实会被替换的文件合并保存一份恢复前备份，再逐份替换；内容相同的文件不重写或备份，不删除快照之后的新记录。整批不是跨文件事务。中断后查看各文件与恢复前备份，再继续。
8. 文档打开只允许常用文档扩展名或目录；不执行 Vault 中的程序、脚本或任意协议。HTTP 链接只允许 http(s)，Obsidian 协议由服务构造。
9. 每个请求绑定本次 Vault 连接的随机 ID；另一个窗口切换后旧窗口停止读写，表单输入保留。关闭后的实例拒绝迟到写请求。非法 UTF-8 显示诊断并拒绝修改，避免解码替换字符损坏原始字节。

## 真实边界

工作空间删除使用两步预检与确认：服务按直接父级关系计算完整子树，客户端确认后提交每个记录的 revision；提交时重新计算范围，新增下级、正文变化、重复 ID、Vault 诊断或实际记录引用均阻止执行。被资源引用的管理文件也禁止删除。备份保存所有原始 Markdown，按待办 → 节点 → 业务线 → 项目的顺序逐文件暂存到 `.atlas/trash/<备份 ID>/<原路径>`，绑定的笔记和资源不随计划删除。成功后快照标记为 delete，移除内容相同的暂存副本，删除快照仅保留最近一份。中断时尝试用不覆盖目标的硬链接还原；完全还原时移除本次临时快照，未能还原时保留 recovery 快照和回收原件。进程退出遗留的 recovery 资料不自动清理。删除与多文件恢复均不是跨文件事务，也无法锁住外部编辑器的并发文件操作。

- 哈希最后检查和 rename 之间仍有很窄的外部编辑竞态；Node 没有跨平台文件 CAS。请避免在两个编辑器同时修改同一个结构化字段；使用 Vault 全量版本备份。备份保护原始内容，但不能宣称任意外部进程并发下绝对事务安全。
- Junction 检查不是针对恶意本机进程反复替换目录的 OS 级隔离。Vault 应在当前用户控制的本地可信目录中。
- `.atlas/backups` 是管理数据的恢复副本，不包含普通笔记、原生附件、Git 仓库、Obsidian 配置，也不代替全量 Vault 备份。正常最多保留 3 份 manual、1 份 delete、1 份 restore，manual 内容相同时复用。旧版无 kind 的快照按 manual 计数。新建快照后整理超额历史；recovery 资料不自动淘汰。「清理旧备份」另外清除有完整快照且内容一致的回收副本、旧版普通笔记 UUID 历史副本，未知文件与改动过的回收副本保留，不能通过此入口删除当前 Markdown。
- 异常退出的 service.lock 不自动抢占。检查文件内 pid 已退出后，手动移除锁文件再连接；正常 Ctrl+C 会释放锁。
- 时间段是本地日期与墙钟时间，输入精确到分钟，拖动吸附为 15 分钟，跨午夜拆成两条；全天末端可为 24:00。R0 不进行时区换算和夏令时耗时校正。
- 启动后需选择 Vault；不把路径、token 或业务数据写入浏览器持久化。

## 截止点与实际关联

节点时刻与截止日期配对，日期未定时不能单填时刻。节点仅在截止当天显示，按截止时刻定位为点，没有时间范围；未设时刻单独列出。开始日期 / 起止时刻已从节点契约移除，不批量迁移用户 Vault；含已删除字段的管理记录会显示诊断，原文件保持原样。

实际区块仍有 date、startTime、endTime。workedTodoIds 保存本段推进但未完成的待办，completedTodoIds 保存本段完成的待办；同一 ID 在同一区块只放其中一处，界面合并显示关联关系。一个待办可被多段推进记录引用，但只能有一段完成证据。项目归属从两类关联的并集推导，待办状态只由完成证据联动。
