# Android 本地版：构建、预览与验收

Android 使用 Capacitor 7 承载现有 React 界面。共享 `WorkspaceService`、`Workspace`、领域契约、Markdown 与 Notes 实现直接编译到本机运行时，不启动 Windows 服务，不复制业务规则，日常本地工作不依赖网络。基于 Windows main `261b1ad`（v0.1.6）开发，桌面仍使用原四页布局。

后续 Windows 与 Android 的新增业务继续在同一主干和共享核心实现；本次保留 Windows 界面只约束本次变更，不限制后续两端共同开发。分工与验收约定见[共用底座的开发约定](../architecture/repository.md#后续-windows-与-android-共用底座的开发约定)。

Android 图形与 `apps/web/public/chaos.svg` 的 C 形路径、29 单位笔画及金色圆点一致。Android 8 及以上使用 `mipmap-anydpi-v26/chaos_launcher.xml` 自适应图标，暖绿底色与透明 `drawable/chaos_mark.xml` 分离，旧系统通过 `mipmap-anydpi/chaos_launcher.xml` 引用 `drawable/chaos_icon.xml`。启动页使用整屏暖绿和透明标志，系统栏同色，并在 WebView 首帧可绘制后移交页面。HTML 启动占位也使用同色背景和网页 logo。修改品牌图形时需同步网页 SVG 与这两个原生矢量资源。测试截图、复制的网页资产、构建目录、工具链和签名凭据继续留在忽略目录；正常源码图片不作全局忽略。

## 已明确的手机界面

用户在 2026-11-03 明确要求 Android 使用独立导航与页面组合。这是对默认“手机仅窄屏重排”的界面范围扩展，Windows 不随之调整。

| 手机入口 | 单一职责                                               | 复用内容                                                                      |
| -------- | ------------------------------------------------------ | ----------------------------------------------------------------------------- |
| 编辑     | 记录实际，或快速新建待办／想法／节点；一次展示一个表单 | ActualRecordForm、QuickCapture、关联选择与领域校验；完整编辑复用 WorkItemForm |
| 已做     | 查看当天实际投入并修改记录                             | ActualRecordList、ActualRecordForm、timeTotals                                |
| 待做     | 当天安排、逾期处理与待联系对象                         | TodayAgenda、OverdueEvents、OverdueTodos、contactsForDay                      |
| 空间     | 先选择项目与业务线，再查看一条竖向业务线               | workspaceGroups、完成与日期排序查询、现有编辑／删除表单                       |
| 回顾     | 周投入、完成情况、每日计划与实际及已有复盘             | 现有 Review 及按需加载的 FullCalendar                                         |
| 笔记     | 同一套业务线导览，阅读／编辑 Notes，快速追加随手记     | NotesContent、notes.read、notes.save                                          |

按 2026-11-04 用户要求，项目以标题分组，下面列出重要性圆点与业务线名称，组末用加号新增业务线。空间与笔记共用此清单。进入业务线后，日期与标签在轴左，标题与条目在轴右，待办池固定末端。左右滑动切线，同时提供上一条／下一条按钮。正文采用 16px 本地打包的 Noto Serif SC（与思源宋体同源），标题加重，操作与日期沿用易辨认的系统无衬线字体。更多菜单承接触摸编辑、完成、日期、重要性、移动／排序、批注、升线和删除。

本次界面调整基于 main `e19cc61`。手机输入使用低对比填色，按钮减少边框，实际／待办切换铺满可用宽度并使用平滑指示背景。开始与结束时间并排，日期选择保留系统日历入口并去掉外框，笔记追加和正文编辑采用带可访问名称的图标。网页和手机的可选字段、实际关联与关联批注直接展示，两端继续调用同一份表单和业务服务。

随手记直接追加至所属业务线 Notes，不增加备忘录数据表或正文副本。表单、批注和笔记通过本机草稿保留修改，冲突时继续保留输入。项目和业务线删除仍额外确认。现有完整复盘文章展示继续沿用，未增加独立的复盘编辑工作流。

表单、实际关联与批注、随手记和 Notes 编辑草稿现按工作目录与对象保存到设备本机 localStorage，切换页面或刷新后恢复。成功保存或明确清空会清理对应草稿。已有对象的草稿保留开始编辑时的 revision，恢复后仍拒绝覆盖外部更新。只有本机存储失败时，离开前才要求确认，草稿不参与交换或业务统计。

Android 通过长按实际记录打开修改／删除操作，网页使用右键或 Shift+F10，均调用 `actual.delete` 并校验 revision。删除实际记录保留已发布的完成事实与 Notes。关联待选以当前快照中的对象为准，删除后清理失效选择，按记录日期优先再按节点日期和时刻排列。业务线入口的快速识别保持已经选定的项目与业务线。

过期事件弹窗使用整页滚动和透明日期入口，Android 返回键优先关闭最上层弹窗，改期等待时也可返回。开始与结束均使用系统时间选择器，结束选择 00:00 表达当日 24:00。

性能路径沿用内容 SHA-256 校验。共享保存改为只读回本次发布的记录。原生查找现有文件直接查询已授权树下的完整文档 ID，缺失路径再逐级区分不存在与授权错误。Android 的每次真实扫描仍读取内容指纹，相同指纹复用解析结果，成功提交后从同批文件构建可交付快照，前端只消费一次并保护请求顺序和目录会话。

本期不包含 QQ／微信接入、AI 服务、自动同步、二维码交换或后台任务。桌面的这些入口和能力保持现状。

2026-11-03 新增用户主动触发的 Wi-Fi 直连增量交换，两端在“设置 → 设备增量交换”开启连接、发送、预览与确认；回执自动返回。离线时可通过系统文件选择器读取／保存同一格式的 JSON。业务导入由同一 `WorkspaceService` 原子执行，不在 Java 桥中改写工作记录。格式、操作步骤及删除／附件限制见[交换协议](../architecture/exchange.md)；完整功能覆盖与缺口见[Android 业务覆盖核对](android-feature-coverage.md)。

2026-11-04 增加目录连接、启动读取及交换过程的阶段、实际计数和计时反馈。读取可停止，原生调用有超时提示，网络使用独立线程。SAF 文件定位使用所支持本地提供方的文档 ID 精确查询，减少反复枚举同级文件。重新安装后优先沿用系统稳定设备标识，旧版随机标识遗留的目录须在系统选择器中重新选择，再确认“接管并恢复”。接管仍检查当前运行锁，并先恢复未完成发布。电脑配对二维码由手机离线扫码识别，配对信息仍只保留在会话中。

## 文件能力与限制

- 通过系统 `ACTION_OPEN_DOCUMENT_TREE` 选择目录并记住持久授权，不要求全盘权限。
- 首版只接受内部存储的 `com.android.externalstorage.documents` 本地提供方。SD 卡和云盘提供方明确拒绝，不能把 URI 转换成磁盘绝对路径。
- 连接时验证创建、严格读取、fsync、无覆盖重命名及删除能力。文件原文 SHA-256 作为 revision，非法 UTF-8、重复 ID 与外部修改均明确诊断。
- 同一目录使用进程文件锁与设备归属标记。所有文件请求在单线程执行器中串行；快照与共享业务读写还经过 Workspace 串行边界。
- 多文件修改先发布 `.atlas/pending.json`。版本 2 日志一次记录整批原文与新文的暂存路径，独立文件最多四路并行发布，逐文件继续校验内容版本，整批结束前阻止其他业务读取。旧版数组日志与 `.atlas/android-swap.json` 仅在恢复既有未完成发布时沿用。中断后重新连接恢复，发现第三种内容则停止，不覆盖。未完成批次期间拒绝其他写入。
- 日志的 `.preparing` 文件尚未授权业务写入，重连时清理；已发布日志与原文暂存保留到操作完成。这些只用于未完成操作恢复，不是自动备份或操作历史。
- 备份仍由用户手动创建，最多三份；只包含受管 Markdown。恢复按稳定 UUID 定位当前文件并校验预期版本。
- “导出完整目录”通过系统文件选择器写 ZIP，包含普通工作文件和附件，排除运行锁、发布日志、内部配置、`.git`、`.obsidian`、node_modules。导出前必须不存在未完成批次；它不承担增量同步或覆盖导入。
- 资源打开沿用授权边界与文档类型限制。其他设备上的绝对路径不能在 Android 打开；手机也需要安装能打开相应文件的应用。
- 配置只存本机 SharedPreferences；系统自动备份关闭。Capacitor 调用日志关闭，避免将工作正文记录到平台日志。开发 APK 的调试桥仅用于本机验收；正式发布需另行签名。

SAF 没有被当作 NTFS 原子替换。这里验证的是指定本地提供方上的可恢复发布；不能将模拟器测试视为任意厂商设备、任意存储提供方或真实断电的证明。

## 电脑上的快速界面预览

需要直接双击体验时，使用本地 `releases/CHAOS-Android-Preview-0.1.6-Setup.exe`：按当前用户安装，无需管理员权限、Node.js、Android Studio 或模拟器。安装后打开“CHAOS Android 界面预览”，默认 390×844 竖屏窗口，可调整宽度，用鼠标点击、滚动与拖动切线。它运行和 APK 相同的六入口 React 界面，业务仍由同一份 `WorkspaceService` 执行。

预览 EXE 使用 Windows 本地文件适配，**不是 Android 系统模拟器**。首次在 `%APPDATA%/CHAOS-Android-Preview/sample-workspace` 创建合成示例，后续保留测试修改；配置和浏览器数据与 Windows 正式版隔离，每次启动默认回到示例目录。卸载不删除这个目录。安装包和便携预览 EXE 只放本地 `releases/`，不提交，也不创建 GitHub Release。

```powershell
npm run package:android:preview
npm run test:android:preview
```

打包复用现有 Electron 外壳，使用固定 SHA-256 校验的官方 NSIS 3.11 便携编译器生成单个安装 EXE；工具缓存被 Git 忽略，不全局安装依赖。自动验收安装后的真实 EXE、六页切换、完成、Notes／实际保存、隔离配置、重启恢复和卸载保留额外文件。手机软键盘、系统栏、返回键、SAF 权限与 Android 文件安全仍使用 APK／模拟器验证，不能由这个 EXE 证明。

开发时也可以不打包：

```powershell
npm ci
npm run preview:android
```

打开 http://127.0.0.1:4320/?ui=android。预览使用 `.test-vault/android-preview` 合成目录与单独配置，不连接用户的真实目录；Ctrl+C 退出。该入口使用真实共享业务服务，可验证页面交互，但不代替 Android 文件能力测试。

默认 `/` 继续打开 Windows 原界面；`?ui=android` 只选择手机页面组合，不改变后端业务规则。已有 React 表单、控件和查询直接复用，不通过工具自动生成另一套原生业务页面。

## 构建与 Android Studio

需要 Node >=22.12、JDK 21、Android SDK 35、平台工具与 Android Studio 模拟器。设置 `JAVA_HOME` 与 `ANDROID_HOME` 后：

```powershell
npm run package:android
npm run android:open
```

构建脚本也识别本机 `.android-tools/jdk`、`.android-tools/sdk` 和 `.android-tools/gradle`。这些工具、Gradle 缓存、本地 SDK 路径和开发签名全部被 Git 忽略。使用 Android Studio 的 Device Manager 启动 Android 35 模拟器后，可直接运行 App 并查看 Logcat、布局和 WebView。

开发产物为 `releases/CHAOS-Android-<版本>-debug.apk`，仅含应用代码和界面，不含工作目录。Gradle 默认只构建 `:app` 自身与其测试包，不构建 Capacitor 依赖内部的测试 App。

### 签名发行 APK

`npm run package:android:release` 构建 `releases/CHAOS-Android-<版本>.apk` 与 SHA-256 文件。脚本要求本机存在 `.android-tools/release-signing.properties`，字段为 `storeFile`、`storePassword`、`keyAlias`、`keyPassword`，路径相对 Android Gradle 根目录解析。配置与密钥容器都由 Git 忽略，构建时检查 APK 路径、应用版本、关闭调试标志与签名完整性。

v0.1.7 沿用此前本地测试版的安装证书，并将签名材料保存在独立加密的本机发行容器 `.android-tools/release.keystore` 中，支持直接覆盖升级。发行构建关闭应用调试、WebView 远程调试和调试故障注入。后续覆盖升级继续使用相同安装证书。GitHub Release 的 Windows ZIP 由既有 tag 工作流验收发布，Android 签名 APK 在本机验收后附加到同一版本。

## 可重复的自动验收

```powershell
npm run check
npm run package:android
npm run test:android
```

`test:android` 默认只连接已启动的 `emulator-*` 设备；实体手机需显式指定 `ANDROID_SERIAL`。业务写入只允许使用 `Documents/CHAOS-Android-Test`，拒绝在已连接的个人目录运行写入测试；JSON 传输验收另创建带唯一标识的合成 Downloads 文件，并只删除本次创建的精确文件名。

闭环由现成工具组成：adb 安装／启动 APK；Playwright 通过调试 WebView 操作真实页面；系统 UI Automator 完成 SAF 授权；AndroidJUnitRunner 验证真实文件提供方。CDP 使用 `noDefaults`，避免向 WebView 发送其不支持的浏览器下载配置。

验收包含目录授权、项目／业务线／节点／待办创建、切线、Notes、关闭网络后的实际与完成联合保存、回顾、手动备份、强制终止后离线重启，以及真实 SAF 的 15 处发布中断恢复、第三种内容冲突、路径越界、严格 UTF-8 与目录独占。JSON 用系统选择器读取／保存并回传 Windows；Wi-Fi 使用模拟器网关验证原生 HTTP 密文双向收发和电脑确认。原生测试只在明确的合成目录内运行，故障注入样本验收后按固定、已解析的测试路径清理。

截图、原生测试输出与 JSON 结果写入 `test-results/android/`。浏览器手机回归见 `tests/e2e/mobile-ui.spec.ts`；共享业务适配回归见 `tests/android-runtime.test.ts`。没有执行的真机、磁盘满、实际断电和其他提供方测试必须在交付中区分说明。

修改 UI 后运行 `npm run android:sync` 复制网页资产；纯界面迭代也可先在预览入口闭环，再打 APK 进行键盘、系统栏、返回键和权限验证。
