# Android 开发原则与实施方法

本文是后续 Android、跨端复用及移动适配工作的执行约束，面向开发者与 AI。开始相关修改前，先读根目录 [AGENTS.md](../../AGENTS.md)，再读本文；目录职责和具体业务契约以[仓库分工](../architecture/repository.md)、[标准业务 API](../architecture/business-api.md)及[数据安全约定](../architecture/data-and-safety.md)为准。

## 目标与基线

目标是让手机独立使用普通 Markdown 工作目录，并与 Windows 共用同一套业务能力。Android 接入本身不包含业务规则调整或界面重设计。

本轮 Android 接入基于稳定 main `v0.1.6`（`261b1ad`），本机平台验证记录见 [Android 本地版](android-local.md)。实际开发时记录所基于的稳定 main 提交和 Windows 界面截图；后续用户明确要求并合入主干的变更随主干演进，不把这个版本永久冻结。研究文档中的备选方案不等于已批准实施的功能。

仓库现已增加 Capacitor Android 工程、本地共享业务运行时及 SAF 适配；2026-11-03 用户进一步授权初步增量交换，首版采用[JSON 增量协议](../architecture/exchange.md)，不包含自动或后台联网同步。当前范围、构建、预览及模拟器验收见 [Android 本地版](android-local.md)，功能缺口见[Android 业务覆盖核对](android-feature-coverage.md)。不得把浏览器内存测试通过写成 Android 已可用。

2026-11-03 用户明确授权 Android 独立页面组合：六入口导航、圆圈式项目／业务线导览、竖向业务线与左右切线，以及拆分后的今日与笔记。该授权只改变 Android 界面编排；本文件关于 Windows 界面、共享业务、数据安全和验证的约束继续适用。

## 必须保持的边界

- **业务行为不动**：沿用现有层级、完成、日期、重要性、归属、实际记录、Notes、删除和备份语义；不能以手机实现方便为由改变字段、默认值或流程。
- **Windows 界面不动**：保留四页职责、导航、布局、文案、主题、颜色含义、控件和交互入口。拆分组件必须保持原输出和行为，不顺带做桌面改版或清理无关功能。
- **手机沿用现有界面体系**：复用现有页面、表单、控件与样式。必要适配限于窄屏重排、横向区域转为纵向、滚动、触摸和软键盘可用性；仍表达同一内容和操作，不另造一套业务页面。
- **主干只维护一份规则**：不复制 Windows 业务文件到 Android，不新建手机专用完成、改期、归属或批注服务，不长期保留新旧两条实现路线。
- **用户内容不进入代码或安装包**：真实工作目录、配置、绝对路径、密钥、测试产生的工作内容均不得提交或打包。示例与测试只用合成数据。

若用户明确要求改变业务或界面，按该需求单独界定改动并更新相关契约和回归；不要把 Android 接入当作这些变更的隐含授权。

## 复用路线与文件分工

优先采用现有 React／TypeScript 界面与共享业务核心，加 Android 外壳、调用桥和目录适配。外壳技术在实际开工时依据本机能力确定；不为了预留可能性同时维护 WebView、原生界面和多套存储方案。

| 位置                                              | Android 开发时的职责与限制                                                                                                              |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/domain/`                                | 唯一的记录 Schema、校验、日期、排序、完成推导与标准命令契约；不依赖平台。                                                               |
| `packages/workspace/`                             | 唯一的保存、完成、改期、移动、升线、删除、Notes 与 Markdown 业务实现；Android 适配持久化边界，复用 `WorkspaceService`，不重写业务方法。 |
| `apps/web/src/pages/`、`features/`、`components/` | 复用页面与组件；只提取真正共享的展示和交互，不复制整页或在各组件散布平台判断。                                                          |
| `apps/web/src/api.ts`、`platform/`                | 保留界面调用入口；HTTP、目录选择、资源打开与 Android 受限桥均在平台边界接入。Android 由应用入口安装本机传输，页面不接触文件实现。       |
| `apps/local-service/src/native/`、`apps/desktop/` | 继续负责 Windows 的 Node 文件访问和 Electron 外壳；不能被共享核心或手机 UI 反向导入。                                                   |
| `apps/android/`                                   | 仅负责 Android 生命周期、权限、目录与文件能力、共享业务运行时装配和受限桥接；不得新增另一套业务规则。                                   |

界面经平台调用入口发送标准业务命令，由共享 `WorkspaceService` 执行；Android 文件实现提供 `Workspace` 所需持久化能力。界面不得直接导入存储实现或改写 Markdown。不能用“暂时调用 Windows 本机服务”代替手机离线运行；现有 `127.0.0.1` 服务只监听其所在设备，也不能为省事改成对局域网公开或取消鉴权。

## 状态一致性：保留已修复的单一路线

1. 完成事实只保存 `completedAt`；有条目的普通节点通过共享 `isComplete` 推导，待办池不完成，项目和业务线仍由用户明确完成。不新增 `done`、手机状态表或页面完成缓存作为第二份事实。
2. 手动完成统一使用 `work.complete`。实际记录的 `completeIds` 只是本次提交意图，最终和手动完成进入同一个后端完成函数；关联实际记录本身不代表完成。
3. 日期、重要性、归属等属性来自同一记录与共享快照；批注和纪要通过共享命令进入所属业务线 Notes，同一段正文只保存一份。不能给今日、工作空间或 Android 各存一份属性副本。
4. 排序、划线和完成图标必须使用同一个完成判断。保存成功后从权威结果刷新；请求序号或等价机制丢弃迟到的旧响应，切换目录时使旧请求失效。不得删掉现有保护或靠延时刷新掩盖竞争。
5. 快照和 Notes 读取与写入共用工作区串行边界。实际记录、完成事实、Notes 及必要来源状态按同一业务批次发布，不向界面暴露半个结果。
6. 表单草稿可以本地保留，但不成为另一套业务状态；保存失败或版本冲突时保留草稿，不能先在别处标记完成，再补写文件。

相关回归入口：`tests/e2e/shared-state.spec.ts`、`tests/business-service.test.ts`。调整刷新、缓存或平台传输时必须继续覆盖这些情形。

## Android 目录与文件能力

- 使用 Android 系统目录授权，例如 Storage Access Framework 的目录选择和持久授权。目录 URI 不等于 Windows 路径；不能把 URI 强行转换成绝对路径后套用 Node 文件代码，也不能默认要求全盘权限。
- 普通 Markdown 目录仍是唯一权威源，不能改成数据库／IndexedDB 为主、Markdown 定期导出。若使用应用私有目录，必须提供完整目录的显式导出能力，并说明清除应用数据的影响。
- 首次没有有效本机授权时必须选择目录；后续启动只恢复本机记住的授权。授权失效或目录不可达时提示重新选择，不能静默连接示例目录、创建空库或覆盖旧内容。
- 严格 UTF-8 读取，保留原文、未知 YAML 字段、正文、BOM 和换行；沿用稳定 UUID、重复 ID 诊断和原始内容 SHA-256 revision。修改时间不能代替版本指纹。
- 实现路径／URI 授权范围校验、同一目录的独占写入、串行读写、版本冲突检查、可靠单文件写入和可恢复批次发布。不能直接照搬 Windows PID 锁、NTFS 硬链接或原子重命名假设。
- Android 存储提供方可能是本机、SD 卡或云盘，写入与重命名保证各不相同。先验证拟支持提供方的能力；无法满足安全要求时明确拒绝写入，不能退化为直接覆盖并声称等价安全。
- 进程终止、后台回收、授权撤销、磁盘满或断电后的恢复必须可验证。短期未完成发布日志成功后清除，不发展为逐操作历史或自动备份；手动备份仍最多三份。
- 配置、权限信息和密钥放在设备本机配置中，不放进业务 Markdown、交换包或 APK。QQ／AI 等能力按平台实际支持情况接入，不能把 Windows 脚本或密钥随包复制过去。

## 手机界面适配方法

先用现有页面在窄屏和触摸环境中检查，再针对实际问题做局部调整。以当前控件、暖绿／静蓝主题、字号层级和五档重要性颜色为基准。

- 优先用局部响应式布局完成分栏转单栏、面板依次排列和滚动，不通过修改全局样式改变桌面尺寸与排布。
- 需要拆组件时，先保持桌面渲染等价，再在手机容器中组合；同一表单的校验、草稿与保存行为不复制。
- 悬浮、右键、拖动和键盘快捷操作在手机上提供触摸可达的等价入口；入口可以不同，但调用同一操作，不能衍生第二套编辑流程。
- 检查软键盘遮挡、返回键、焦点、弹窗、长标题、空状态和错误反馈。手机适配前后对比同一份合成数据的桌面截图和关键交互，不能只看手机预览。

## 导出、导入与后续近似同步

首阶段可以只实现手机本地保存和用户手动导出／复制完整工作目录，不把自动同步当作 Android 起步的前置工程。复制前完成或恢复待发布批次，取得一致的内容；运行锁、未完成发布日志、本机配置和密钥不随目录搬迁。导入目标已有内容时先检查冲突，不直接用整包覆盖。

用户后续明确要求二维码、文本或文件增量交换时，再定义一份版本化交换协议：

- 使用稳定对象 UUID、明确的包 ID／操作 ID 和源版本信息识别对象、去重与冲突；标题、排序、时间戳或“最后一条消息”不能单独作为增量依据。
- 多段消息或分片二维码要带同一包标识、分片序号／总数和完整性校验，收齐并校验后再提交；不能边扫码边写入半个业务批次。
- 先展示变更并校验，再映射为共享业务命令；传输／解码层不得提交任意文件路径或直接执行 `FileChange`。重复导入、外部修改、删除、缺失关联和协议版本不兼容的行为必须在协议中明确，不猜测合并或静默覆盖。
- `Snapshot.vaultId` 是目录连接会话标识，不是跨设备工作区身份；本机 revision 是内容版本，不是同步游标；pending 日志和内部 `FileChange` 不是交换协议。
- 同步不能另存一套完成、批注或重要性，也不自动引入云服务、持续历史、回收区或删除墓碑。确有需求时先定义必要边界，再修改同一主干契约和服务。

## 实施顺序与交付检查

1. 阅读上述约束，记录稳定 main 基线；列出本次文件、平台能力和可验收范围。只添加实际需要的 Android 工程与依赖，不先搭建多套未来方案。
2. 用合成工作目录接通目录授权、读取、保存、冲突与中断恢复；先证明 Android 持久化满足共享核心要求，再开放编辑。
3. 接入共享业务服务与现有前端调用入口；先验证无 UI 改版时的创建、完成、实际记录、Notes、改期、移动、升线和删除。
4. 针对手机屏幕做必要适配，每次都对比桌面基线。平台差异留在边界，业务修复进入共享核心，不增加 Android 特例规则。
5. 同一个仓库、主干和变更中维护契约、共享实现、平台适配、文档及必要回归；不维护长期 Android 业务分叉。新目录的依赖方向纳入 `scripts/check-boundaries.mjs`，不能为通过检查而放宽核心边界。
6. 提交前运行 `npm run check`；涉及桌面调用、存储或打包时，另运行 `npm run package:desktop` 和 `npm run test:release -- <最终ZIP路径>`。新增 Android 工程后补充其构建、模拟器及真机验证，不能仅以网页窄屏测试替代。
7. Android 必须验证真实目录授权、离线重启、后台终止、授权撤销、写入失败、外部修改冲突、重复 ID、长内容和两端 Markdown 互读。文件能力测试用独立目录，不能连接用户真实工作区。
8. 交付说明列明改动、验证、未支持能力和限制，明确 Windows 业务与界面对比结果。Windows／Android 各自产物在验证后发布；尚未构建或验收的平台不能标记为已支持。APK 签名凭据不入库，`releases/` 只放忽略的构建产物。

检查变更时，若出现第二套业务服务、第二份完成状态、绕过 revision 的覆盖、直接写 Markdown 的 UI／扫码代码，或无关桌面样式变动，应回到上述单一路线整合后再交付。
